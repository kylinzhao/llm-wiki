# 历史数据探查指南

当 PRD 涉及以下任何一项时，必须执行历史数据分析（与代码搜索并行执行）：

- 新增/修改数据库字段、表结构
- 新增/修改业务规则（校验、计算、状态流转）
- 新增/修改枚举值或配置项
- 报表/统计口径变更
- 数据展示或查询条件变更

不涉及以上变更时，在报告中注明"不适用"即可。

## 1. 识别历史数据现状

### 表结构分析
- 根据代码搜索到的 Mapper/Model/Entity，定位相关的数据库表
- 分析每张表的结构：字段定义、枚举值范围、关联关系

### 数据量级与分布
- 能访问数据库则查询：总记录数、按时间段的分布、关键字段的值分布、空值/默认值比例
- 无法访问时基于代码推断，并标注"需人工确认"

### 数据质量探查

| 质量维度 | 探查内容 |
|---------|---------|
| 重复数据 | 同一业务实体是否存在多条记录？重复比例多少？ |
| 格式一致性 | 同一字段是否混用多种格式（如手机号有无区号、日期格式不统一、金额单位不一致）？ |
| 异常值 | 是否存在明显超出合理范围的值（如负数金额、未来日期、超长字符串）？ |
| 关联完整性 | 外键指向的记录是否存在？是否有孤立数据？ |
| 业务一致性 | 同一业务流程的数据是否完整（如订单存在但对应的车辆记录缺失）？ |

## 2. 差异分析：历史数据 vs 新需求

### 逐字段对照
- 新需求新增了哪些字段？历史数据中这些字段的值为空/null？
- 新增 NOT NULL 约束 → 历史数据是否有空值？
- 新增枚举校验 → 历史数据是否有超出新枚举范围的值？

### 逐规则对照
- 新增计算规则 → 用新规则重新计算，结果是否与历史值一致？
- 新增状态流转 → 历史数据中的当前状态能否匹配新状态机？

### 逐场景对照
- 列表页展示：老数据缺少新字段时展示什么？
- 搜索/筛选：老数据不满足新筛选条件时是否被过滤？
- 报表/统计：老数据纳入统计还是排除？

### 数据质量差异
- 新增唯一约束 → 是否存在重复数据需要先去重？
- 新增格式校验 → 是否存在格式不合规的数据需要先纠正？
- 新增关联校验 → 是否存在孤立数据需要先补全或清理？
- 新增业务规则 → 是否有不满足新规则的历史数据需要标记或修正？

## 3. 处理决策矩阵

输出格式：

```
| 场景 | 影响范围 | 不处理的后果 | 是否需要处理 | 处理优先级 |
|------|---------|-------------|------------|-----------|
```

判断标准：

| 级别 | 标准 | 示例 |
|------|------|------|
| **必须处理** | 不处理会导致功能报错、数据不一致、用户困惑、新规则上线后阻断历史数据流转 | NOT NULL 字段无值、唯一约束冲突、统计口径变更导致报表跳变 |
| **建议处理** | 不处理不会报错但影响体验 | 展示空白、排序异常、搜索结果不准 |
| **可暂不处理** | 影响极小或自然衰减 | 新功能上线后老数据不再被访问 |

## 4. 处理方案建议

每种方案都必须包含：执行时机（上线前/上线后/过渡期）、预计耗时、回滚方案、验证方法。

### 数据回填
为新增字段填充默认值/计算值。
- 明确回填规则（默认值？计算公式？）
- 明确执行时机
- 明确回滚方案

### 数据迁移
将数据从旧结构转换到新结构。
- 明确迁移脚本
- 批次策略（全量还是分批？每批多大？）
- 验证方法（总数对账？抽样检查？业务规则校验？）

### 数据清洗
处理不符合新规则的历史数据。
- 去重策略：保留哪条（最新？最完整？人工确认？）、去重后的关联数据如何处理
- 纠正策略：格式统一、异常值修正规则、缺失值补全规则
- 清理策略：无效数据归档还是删除、清理范围、备份方案
- 验证策略：清洗后如何验证正确性

### 兼容展示
在展示层兼容老数据。
- null 时显示什么（如"暂无"）
- 兼容策略和退出时间

### 双写/过渡期
新老规则并行一段时间。
- 过渡时长
- 切换条件
- 并行期间的数据一致性保障
