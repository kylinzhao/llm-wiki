## 1. 评分概览（所有模式必须）

```markdown
## [需求名称] — 需求评审报告

**评审日期**:
**需求来源**:
**评审模式**: 完整评审 / 产品评审 / 快速评审（维度 X, Y, Z）/ 评分概览

---

### 维度评分卡

| 维度 | 名称 | 评分 | 一句话说明 |
|------|------|------|-----------|
| 1 | 背景与目标 | ✅/⚠️/❌ | |
| 2 | 业务概念定义 | ✅/⚠️/❌ | |
| 3 | 业务流程 | ✅/⚠️/❌ | |
| 4 | 领域边界 | ✅/⚠️/❌ | |
| 5 | 功能需求完整性 | ✅/⚠️/❌ | |
| 6 | 数据口径 | ✅/⚠️/❌ | |
| 7 | 规则清晰度 | ✅/⚠️/❌ | |
| 8 | 技术约束 | ✅/⚠️/❌ | |
| 9 | 已有实现差异 | ✅/⚠️/❌ | |
| 10 | 依赖方 | ✅/⚠️/❌ | |
| 11 | 实现成本 | ✅/⚠️/❌ | |
| 12 | 性能 | ✅/⚠️/❌ | |
| 13 | 假设与限制条件 | ✅/⚠️/❌ | |
| 14 | 风险 | ✅/⚠️/❌ | |
| 15 | 成功标准 | ✅/⚠️/❌ | |
| 16 | 上线与兼容性 | ✅/⚠️/❌ | |

**评分统计**: ✅ × 个 / ⚠️ × 个 / ❌ × 个
```

产品评审模式下，评分卡仅包含 10 个产品维度（1,2,3,5,6,7,13,14,15,16），跳过技术维度（4,8,9,10,11,12）。

评分模式下，只输出上面的内容即可。

### PRD 质量门禁

完整评审、产品评审、以及判断“是否可进入开发/研发评审”的快速评审必须输出：

```markdown
### PRD 质量门禁

| 门禁项 | 结论 | 主要缺口 | 影响等级 |
|------|------|---------|---------|
| 文档结构 | 通过/部分/未通过 | | P0/P1/P2/- |
| 调研证据和目标闭环 | 通过/部分/未通过 | | P0/P1/P2/- |
| 生命周期交付物 | 通过/部分/未通过 | | P0/P1/P2/- |
| 用例化需求 | 通过/部分/未通过 | | P0/P1/P2/- |
| 流程图质量 | 通过/部分/未通过 | | P0/P1/P2/- |
| 名词和实体 | 通过/部分/未通过 | | P0/P1/P2/- |
| 字段、状态和断点 | 通过/部分/未通过 | | P0/P1/P2/- |
| 数据、埋点和统计 | 通过/部分/未通过 | | P0/P1/P2/- |
| 配置、权限、消息和上线 | 通过/部分/未通过 | | P0/P1/P2/- |
```

## 2. 完整/快速评审详细内容

在评分概览之后，按以下顺序输出。

### 已有实现差异对照表

```markdown
### 已有实现差异对照表

| PRD 功能点 | 已有实现 | 代码位置 | 一致性 | 数据层面影响 |
|-----------|---------|---------|--------|------------|

（维度 9 产出。空项目注明"不适用：空项目无已有实现"）
```

### 历史数据分析报告

读取 `references/historical-data-analysis.md` 中的输出模板。不涉及数据变更时注明"不适用"。

### 维度详情

```markdown

（具体问题，引用文档内容。无问题则简要注明原因）

...

...

（必须包含实现范围确认清单）

```

## 5. 评审统计

```markdown
## 评审统计

- **评审模式**：完整评审 / 产品评审 / 快速评审 / 评分概览
- **维度覆盖**：16/16 或 10/16（产品评审）（X 个有问题，Y 个无问题，Z 个不适用）
- **维度评分**：✅ × 个 / ⚠️ × 个 / ❌ × 个
- **问题分布**：P0 × 个 / P1 × 个 / P2 × 个
- **角色问题**：技术Leader × 个 / 架构师 × 个 / 后端 × 个 / 前端 × 个 / 测试 × 个 / 产品经理 × 个
- **已实现功能**：× 项（不需要改动）
- **历史数据影响**：涉及 × 张表 / × 条记录需处理
- **真实工作量**：与 PRD 描述的差异说明
```
